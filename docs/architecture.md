# Architecture

The live source of truth is one Scintilla buffer per tab (`PromptEditor`). Scintilla positions, section ranges, search results and saved document bytes use UTF-8 byte offsets. Qt's `QString` and regular-expression captures use UTF-16 indices; `FindReplace` converts capture spans to byte offsets before any editor operation. Derived outline parsing runs in a QtConcurrent worker after an edit debounce; the result is applied on the GUI thread only if its captured revision is still current. Scintilla's upstream Qt integration is compiled from `vendor/scintilla/qt/ScintillaEditBase`; the Markdown lexer is compiled from upstream Lexilla.

`MainWindow` owns the frameless, resizable 420 × 352 editor window, tabs, native menus, on-demand dialogs, clipboard actions, file watching and timers. One document fills the content area and hides the tab strip. The top-right trigger only becomes visible on hover/focus unless the user chooses to keep it visible. The lazy `LibraryPanel` is a separate native Qt tool window; it reads actual SQLite folders, drafts and templates on opening, searches on demand, and positions itself beside the editor when the screen has room. An opening or switching action flushes the current recovery draft first. A template creates a new independent document with its own ID.

The editor's top strip and Preview caption row drag the editor; its edges and corners resize it. `LibraryPanel` owns only its title-row drag gesture and emits start/finish events. `MainWindow` owns the library's single placement state (automatic, four snapped sides, or free). While snapped, the library follows editor movement and placement is adjusted to available screen space; while free, moving or resizing the editor leaves the library in place. The selected side and free geometry are saved in `QSettings`. The library opening animation is stopped before a drag or side change so it cannot overwrite the chosen position. On a display too small to hold both minimum widget sizes side by side, a requested placement may not fit without overlap; the native manual checklist covers this boundary.

`PromptEditor` subclasses upstream Scintilla's Qt adapter to expose a contextual-formatting signal from Scintilla's viewport context-menu event. Formatting changes UTF-8 byte ranges inside one Scintilla undo action. The optional `QTextBrowser` Markdown preview is created only when requested, uses the live Scintilla buffer, blocks external resources and link navigation, and is destroyed on return to Editor. Qt Markdown's inline HTML support is enabled so `<u>` from Underline renders; the browser executes no scripts and its resource provider returns no external data. Split Preview rebuilds after a 280 ms edit debounce. Preview retains Qt's default heading type scale, which is larger than the Figma reference. Document records hold paths, saved hashes, BOM flag, caret/scroll state and whether a waiting caller owns a tab. `FileIO` validates UTF-8, preserves raw newline bytes and an existing BOM, and uses `QSaveFile` with direct-write fallback disabled. The expected disk hash is checked before replacement and again immediately before commit. A concurrent writer can still race after that final check; there is no cross-process file lock.

Preview's visible Edit button and Escape shortcut return to the existing Scintilla buffer. The button queues the transition to the next Qt event loop pass so its own widget is not destroyed during its click handler. Editor text, selection, first visible line and undo history remain in Scintilla throughout the view change.

`Store` uses SQLite schema version 2 for draft metadata/content, session ordering, folders, reusable template copies, up to 20 checkpoints per draft, and snippet records. The migration adds folders and templates without changing legacy draft IDs or content; removing a folder leaves its prompts and templates unfiled. A separate raw recovery file per modified/unnamed draft gives a simple readable fallback if the database becomes damaged. Snippet content is a regular UTF-8 file inside the app-owned profile. Settings use `QSettings`; profile data uses `QStandardPaths::AppDataLocation`. There is one GUI-thread SQLite connection. Library queries are limited to 200 rows per kind, search, backup snapshots and applying fold levels currently run on the GUI thread, which can cause pauses for unusually large document libraries or prompts.

The executable serves both as the app and as a short-lived command-line forwarder. `QLocalServer`/`QLocalSocket` carry length-prefixed JSON with a 64 KiB frame cap, a narrow command allowlist, request IDs and a per-user endpoint. Each waiting socket is associated with exactly one document. A successful Save and return acknowledges only that socket after saving the target path. The endpoint has Qt's user-access option. There is no HTTP service, helper process or arbitrary command channel.

The app is a Qt Widgets program. It does not load the prompt as instructions, run agents, call models or change external-tool configuration. There are no network requests in the app.

The provisional display name is generated from the CMake project name into `AppIdentity.h`. Stable internal names such as `promptpad.sqlite`, the socket prefix and the command-line executable deliberately remain fixed so a display-name change does not make existing drafts disappear.
