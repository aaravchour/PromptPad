# Files, local drafts and recovery

Editing an unnamed or opened document changes only its Scintilla buffer until an explicit file save. A 650 ms inactivity timer writes a local recovery snapshot; a 5 second maximum timer bounds continuous-typing delay. Every backup copies the current buffer to an app-owned raw `.md` recovery file via `QSaveFile`, then updates the SQLite draft record. The app flushes on normal close and before closing a tab. A process crash can lose the latest unflushed input, up to the timer window plus time spent in a failed or interrupted write. A power failure can have a wider loss window depending on filesystem and hardware. In-session undo is not restored after restart.

On restart, open drafts and their caret/scroll positions are restored. Modified or unnamed drafts prefer the raw recovery file if it is valid UTF-8; otherwise the SQLite snapshot is used. A clean file-backed tab reloads its source file. The title shows a dot for unsaved file changes and a warning mark if the file changed outside PromptPad; save and error notices appear briefly at the bottom. A recovery copy is retained while a file-backed draft remains modified; it is removed after a successful save. Closed drafts remain available through Tools → Browse drafts unless explicitly removed. Tools → Clear checkpoints and closed drafts removes app-owned data and never deletes original external files.

The profile is `QStandardPaths::AppDataLocation` with Qt organization/application name `PromptPad`. The `PROMPTPAD_PROFILE_DIR` override is for isolated tests. The profile directory and recovery files are restricted to the current user on Unix, as is the SQLite file. This is access control, not encryption. The prompt is also exposed to the OS clipboard when copied; maintain your own off-device backups if needed.

Opening accepts UTF-8 text, optionally prefixed by a UTF-8 BOM. NUL and malformed UTF-8 are rejected, so unsupported encodings cannot be silently rewritten. New drafts save as UTF-8 without a BOM and LF line endings. Existing CRLF, LF and CR bytes are read into the editor unchanged and persisted as edited; `SCI_SETEOLMODE` sets the predominant line ending for newly typed lines. Mixed endings can remain mixed. The full source text is copied without UI labels or wrappers; clipboard platform conventions may change newline representation on paste into another application.

Saves use atomic replacement through `QSaveFile`. Missing parent directories, read-only files, symbolic-link save destinations and changed disk hashes report failure. A file watcher gives early visible notice of external changes; the hash comparison at save time is authoritative. On conflict the user can keep editing or use Save As. PromptPad does not overwrite both versions automatically. There is a narrow race after the last hash check and before atomic replacement; a multi-process file lock and merge UI are not implemented.

The database starts at schema version 1 with transactional creation. A newer version is refused; `PRAGMA quick_check` detects damage on open. If it is corrupt, the app does not silently replace the database: raw draft files remain under `recovery/` for manual rescue. Snippet files live under `snippets/`. Checkpoints are named full snapshots stored in SQLite, bounded to the newest 20 per draft; restoring one first backs up the current draft. Clearing history is explicit. There is no cloud sync or automatic backup to another device.
