# Native manual verification checklist

Automated Qt tests use the offscreen platform plugin. Before distributing on each platform, complete and record these checks with a physical display and its native input methods:

- Open a new draft; click into wrapped paragraphs, drag across wraps, select words and lines, edit multiple carets, undo/redo, and drag-select beyond the viewport. Check cursor and selection positions after resizing.
- Compose Chinese/Japanese/Korean text with a system IME. Commit and cancel composition, then undo. Try emoji and combining accents. Check text and caret after save/reopen. Test Arabic/Hebrew bidirectional editing separately; upstream behaviour may be limited.
- Launch with a fresh profile and type immediately without clicking. Check the blank caret, lack of tab strip and panels, and the document title. Reopen with a recovered draft and check caret and scroll position.
- Use keyboard only: focus the hidden top-right trigger and confirm it appears, open the library with `Ctrl/Cmd+.`, search/filter and open an item, close with Escape, and open formatting with `Shift+F10`. Open menus, Find, Snippets and Jump to heading, use multiple tabs, switch Editor/Preview/Split Preview, and Copy Entire Prompt. In Find, open Options and press Escape to return focus to the editor; check that Find and replace shows its second row. Confirm focus is visible in Light and Dark themes. Check standard platform shortcuts against the menu display.
- On large and compact displays, drag the editor top strip and Preview caption row, then resize from each edge and corner. Open the library, drag its title row away from the editor, and confirm editor movement leaves it in place. Drag it near left, right, top and bottom edges to snap; use Library settings → Library position to select each side by keyboard. Move and resize the editor with the library snapped, checking that neither window covers the writing area where both fit on screen. Verify that an in-progress opening animation never moves a newly snapped or dragged library back. Close and reopen the app to check saved window placement. Check hover reveals only the button; click opens the panel. Try reduced motion and the always-visible trigger setting. Test folder creation/rename/remove, prompt move/star/duplicate/remove, search across content, template creation/opening, and that editing a template copy leaves the template unchanged.
- Right-click inside and outside a wrapped selection. Check that the contextual menu follows the click without discarding an in-selection highlight; apply bold, italic, underline, code, link and Turn into, then undo each. Switch to Preview and confirm underline renders without changing the source buffer or undo chain.
- With a screen reader, inspect accessible names, caret and selection announcements, dialog tab order, transient notices and the outline. Record gaps; offscreen tests do not establish accessibility support.
- Set 100%, 150% and 200% scaling where available. Resize to compact width, then toggle View → Comfortable writing width at a wide size. Check that text, selection and caret remain intact and that Find/Replace labels fit. Check modal dialogs, native file dialogs and a usable editor width.
- Save a CRLF file with BOM after changing one line. Compare bytes and reopen. Trigger read-only and external-change save errors; verify status wording. Check native file drag-and-drop and symbolic-link behaviour.
- Copy a selection, then Copy Entire Prompt with folded sections and while Preview is active; paste into a plain text app and compare source bytes, allowing for documented clipboard newline conversion.
- Check Markdown Preview and Split Preview with code fences, Unicode, links and long documents. Use the visible Edit button and Escape to leave full Preview; confirm both restore typing focus. Confirm preview never loads remote resources, keeps source/undo/selection/scroll unchanged, and updates after typing in Split Preview.
- Start two separate `--wait` callers for different paths, cancel one and Save and return the other. Try spaces and Unicode in paths and a same-file collision. Confirm only the correct caller receives success.
- Open/close many long documents and type continuously for at least ten minutes while observing responsiveness and memory. Record OS, hardware, build and metric.

Observed here: macOS arm64 offscreen tests cover Scintilla UTF-8 selection, wrapped mouse selection, undo, context-menu viewport events, editor movement and resizing, all four library placements, independent library dragging, search/filter/template independence, legacy SQLite migration, recovery, preview return and concurrent `--wait`. All five CTest targets pass offscreen. The focused Preview and window-management Qt tests also passed on the native Cocoa platform with synthetic mouse/key events. A full native Cocoa `editor_smoke` run is still unstable across test order: focus on a newly shown window and one delayed fold-level assertion failed in repeated whole-suite runs, while the focused window tests passed separately. Native Cocoa `ui_capture` rendered the light/dark blank, writing, library and preview widgets with temporary synthetic data; the window-management captures show all four library sides and the Preview Edit button. Formatting-menu captures use Qt offscreen because the native popup is drawn outside the widget grab. These are automated/native-rendered captures, not a physical user interaction pass. A physical native IME, screen reader, display-scaling, pointer drag, file-dialog and ten-minute editing pass has **not** been completed. Windows and Linux native passes have **not** been completed.
